HUD Visual Lab

Every window is drawn by a shader, live. Click one to open its settings and turn its parameters while it runs.
Colour --

The parts kit. Every window below the first seventeen is a short list of calls into one shared set of element groups - a tick ring, a bar fan, a selection frame, a fader bank. Press a part under any window to find everything else built from it, or open the settings on a window and turn its parameters while it runs.

How this is built. Each window is one fragment shader that draws shapes from distance fields: a distance to the nearest edge, turned into a crisp line by the screen-space derivative. That is why every window stays sharp at any size, and why the whole page is smaller than one frame of the reference videos.

Adding a visual. Open this file and append one entry to VISUALS. Write vec3 hud(vec2 p), where p is centred on the window, y runs -1..1 and x is scaled by the aspect. Give it a family, tags and a line about what it is for. The window, the labels, the filter and the source view are generated for you. A shader that fails to compile shows its error in its own window instead of breaking the page.

Composing from parts. The element groups live in one block in the prelude, named partTickRing, partRadialBars, partHandles and so on. Each takes a local position, returns light to add, and takes its colour and its rate as arguments - so a part never fights the one beside it, and a whole panel can run off one clock. To place one, move the position: partIris(p - vec2(0.4, 0.0), 0.2, open, 6.0, uAccent). List the parts a visual uses in its parts array and they become the chips under its window.

Settings. Give an entry a params list - {key, label, min, max, step, value} - and each one becomes a uniform float P_<key> your shader can read, plus a slider in the settings window. Click any window to open it. Nothing recompiles while you turn a slider: the value goes straight to the uniform on the next frame, which is exactly how these are meant to be driven from live data in the app. Copy settings gives you the values as JSON, and Copy shader gives you the body with those values written in as defaults.

Taking one into an app. The body of each shader is portable: paste it into a three.js ShaderMaterial for the AR build, or into a Unity Shader Graph Custom Function node, where the renames are mix to lerp, fract to frac, mod to a written-out modulo, and atan(y,x) to atan2.
